How it works

  1. 1

    Add a model

    In Models, paste a public Hugging Face link to a supported model, or import files you already have on the phone. RunLocal picks the right files, downloads them with pause/resume, verifies hashes and installs a private copy.

  2. 2

    Chat

    In Chat, select the model at the top and send a prompt. Replies stream in as they are generated. Image models return pictures right in the conversation with a Save action.

  3. 3

    Keep going offline

    Once a model is installed, nothing needs the network. Switch between saved chats, dictate with the on-device recognizer, and read replies aloud with offline voices.

What's inside

Local text chat

Runs .litertlm models through LiteRT-LM 0.18.1 with proper chat templates and multi-turn history. Choose CPU or GPU per model; a GPU failure is reported, never silently swapped for something else.

Image generation

Stable Diffusion 1.x checkpoints run on the CPU through stable-diffusion.cpp in a separate process, with text-to-image and image-to-image. Generated images are saved privately until you export them.

One-link model setup

Paste a public Hugging Face model or supported LoRA URL. Pinned revisions, publisher hashes, storage and RAM checks, and resumable downloads are handled for you.

Find models you already have

Connect a folder once and RunLocal discovers compatible files, labels unsupported formats honestly, and keeps your originals untouched.

Streaming with real numbers

Every completed reply records decode tokens/sec, time to first token, load time and total time, taken from the engine's own benchmark counters, never guessed from word counts.

Offline voice

Select a downloaded Woof voice in Chat to speak what you type, or dictate with Android's on-device recognizer and read replies with offline voices. Downloaded voice inference remains experimental. Voice by Underdog Woof. There is no network speech fallback.

Model support

RunLocal uses established inference engines and is honest about what they can run. File extensions alone never prove compatibility.

Model typeCurrent support
Text chat Compatible .litertlm containers via LiteRT-LM, CPU or GPU. Public Hugging Face setup and local import. Device-specific NPU variants are excluded.
Text-to-image Complete SD 1.x checkpoints via stable-diffusion.cpp. A known quantized SD 1.5 recipe and supported adapters set up automatically.
Image-to-image SD 1.x with an attached starting image.
MOSS Image SFT Experimental Component pipeline and dependency setup for supported LoRAs. Full phone generation has not been verified yet.
Speech Android offline speech services, plus downloadable English Woof voices (Juno/Mira, experimental). Woof requires non-commercial use and attribution. Other speech model families need compatible runtime adapters.
Video, GGUF text, .task, ONNX, Cactus-native Not supported by the installed runtimes. Recognizable files are still listed with a compatibility label.

Arbitrary Hugging Face repositories are not interchangeable. Gated or private downloads, multi-shard Diffusers pipelines and automatic conversion are not implemented. Model licenses apply separately.

Private by construction

Everything you type, every image you make and every model you install stays on the device.

Never leaves the phone

  • Chats, drafts and history
  • Prompts and generated images
  • Model files and model identifiers
  • Performance metrics for your replies

Uses the network only when you ask

  • Downloading a model you added from Hugging Face
  • Optional daily check of public GitHub release metadata for updates. It can be switched off and sends nothing about you.

No account, no analytics SDKs, no cloud inference fallback, and no broad storage permission. The app uses Android scoped storage and never reads another app's private files.

Build it yourself

The full source is on GitHub under Apache-2.0. You need JDK 21, Android SDK 36, NDK 28.2 and CMake 3.22.

git clone https://github.com/07rjain/runlocal.git
cd runlocal
./scripts/bootstrap-native.sh
./gradlew :app:assembleDebug -Prunlocal.abis=arm64-v8a

Independently built APKs use your own signer and cannot update someone else's installation. See Build and verify in the README.

Questions

Does it really work offline?

Yes. Once a model is installed, text chat, image generation, dictation and read-aloud all work in airplane mode. The network is only used when you add a model from Hugging Face, or for the optional update check that you can disable.

Which phones can run it?

Any 64-bit ARM phone on Android 12 or later can install it. How well a model runs depends on RAM, chipset and the model size. The app checks available memory before loading and tells you when a model is too large instead of crashing silently. Current testing targets the Motorola Edge 60 Pro; physical-device acceptance is still in progress.

Can I use any model from Hugging Face?

No. Text models must be .litertlm containers for LiteRT-LM, and image models must be complete SD 1.x checkpoints or supported adapters with a matching base. RunLocal reads public repositories, chooses the right files and verifies them, but it does not convert formats or run repository code.

What do the speed numbers mean?

Each finished reply shows decode tokens per second, time to first token and total time. These come from the LiteRT-LM runtime's own benchmark counters for that reply. When a model or backend does not report them, the app says "unavailable" rather than estimating.

Is it finished?

Not yet. The current build is a release candidate. The code compiles, unit tests pass and APKs are verified for signing and alignment, but the acceptance checklist on a physical phone is still open. Read V1-READINESS.md for exactly what remains.

Is it related to Cactus, Google or Hugging Face?

No. RunLocal is an independent project. It uses the open-source LiteRT-LM runtime and stable-diffusion.cpp, and downloads public files from Hugging Face when you ask it to. Cactus was studied during prototyping but none of its code is included.
