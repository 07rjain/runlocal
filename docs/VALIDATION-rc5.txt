RunLocal 1.0.0-rc5 · versionCode 11 · ARM64 · Android 12+

Startup-crash investigation
---------------------------
Inspected the actual published rc4 release APK downloaded from GitHub, not only
the source manifest. Its permissions omit android.permission.ACCESS_NETWORK_STATE.

MainActivity.onResume calls checkAppUpdates, which synchronously invokes
UpdateNotifications.schedule. Automatic checks default to enabled in official
builds. The scheduler creates a persisted job with NETWORK_TYPE_ANY. On Android
14+ for apps targeting API 34+, scheduling a network-constrained job without
ACCESS_NETWORK_STATE throws SecurityException. The exception is not caught on
this startup path. RunLocal targets API 36. No model needs to be loaded for this
failure path to execute.

Platform requirement:
https://developer.android.com/about/versions/14/behavior-changes-14#jobscheduler

Fix: declare the normal ACCESS_NETWORK_STATE permission, keeping update behavior
and data unchanged. No runtime permission dialog is needed for this permission.
The packaging verifier now rejects APKs missing it. Running the new verifier
against the downloaded rc4 APK fails with the expected missing-permission error.
The candidate retains app.pocket.local and increases the version code from 10
to 11. Signing continuity was checked against the actual published rc4 APK.
